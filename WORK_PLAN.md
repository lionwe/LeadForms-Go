# LeadForms Go: план робіт

## Мета

Зменшити шум від тестових і бот-заявок, вчасно виявляти недоступні інтеграції та безпечно передавати відповідальність за заявку між менеджерами в Telegram.

## Принципи

- Підозрілі заявки не видаляються автоматично: вони лишаються в історії з поясненням ознаки.
- Тестові й позначені як підозрілі заявки не входять у звичайну статистику лідів; для них доступні окремі фільтри історії.
- Сповіщення про вимкнення інтеграції мають іти резервним каналом, який не залежить від інтеграції, що відмовила.
- Передача відповідального менеджера відбувається лише після рішення поточного відповідального.
- Зміни враховують наявні локальні правки та знімки маршрутів доставки.

- [x] Додати фільтр історії: усі / звичайні / тестові / підозра на бота; показувати причину позначки.

## Поточний статус

Реалізація та локальні регресійні перевірки готові. Повторно пройшли `npm test` (усі п'ять наборів), PHP lint (46 PHP-файлів) і `git diff --check`. Додатковий `tests/mysql-assignment-run.php` раніше перевірено на LocalWP MySQL через завантажений extension і session-only таблицю; міграції й реальні таблиці сайту не зачіпалися. Для повтору передай `LFG_TEST_DB_HOST=127.0.0.1:10023`, `LFG_TEST_DB_NAME`, `LFG_TEST_DB_USER`, `LFG_TEST_DB_PASSWORD`, `LFG_TEST_WP_ROOT` і запусти скрипт PHP з extension `mysqli`. Повний прогін WordPress/зовнішніх API лишається відкритим: конфігурований для цього сайту MySQL-порт зараз не слухає; доступний порт `10023` належить іншому запущеному LocalWP-контексту, тому не використовувався для створення тестової БД. Для закриття пункту потрібен запущений окремий тестовий сайт із sandbox-підключеннями Telegram / Google Sheets / CRM, щоб не запускати міграції чи надсилати повідомлення/рядки в робочі інтеграції. Класифікація ботів є евристичною за текстом/номерами (короткі, повторювані та послідовні шаблони довжиною від 8 цифр), а не безпомилковим визначенням джерела заявки; налаштовувані правила потребують окремого узгодження.
